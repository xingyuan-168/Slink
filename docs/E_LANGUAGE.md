# GameWindowMapper 使用说明

这是供 **32 位易语言程序**调用的屏幕墙 DLL。把 `GameWindowMapper.dll` 放到你的 EXE 同目录。本版虚拟屏功能面向 Windows 10 1903+ / Windows 11 的 **x64 系统**，需要支持 WGC / D3D11 的图形环境；本轮在 Windows 11 x64 验证。源窗口可以来自 32 位或 64 位程序。

**只有一个命令：开始映射，原 14 个参数不变。右键格子可隐藏／显示源窗口。关闭画布先恢复隐藏窗口，再自动释放本次映射资源；恢复失败时保留画布并提供重试，无需调用停止或释放命令。修改参数需要关闭后重新开始。**

本次交付仅包含 DLL 和本说明。LOGO 已嵌入 DLL，用于画布标题栏、任务栏及 Alt+Tab；DLL 在宿主进程内运行，不会修改你的易语言 EXE 程序图标。

验证状态（2026-10-10 候选构建）：虚拟屏后端、部分原生交互、GPU 铺满及请求去重已验证；异步控制修订后的最终三窗口启闭检查因 Windows 拒绝访问输入桌面而尚未完成。此文件不代表最终验收通过。易语言与大漠可沿用原例子人工验收，发现问题请按第7节反馈。

## 1. 易语言 DLL 声明

删除旧版声明，使用下面完整的 **14 参数**声明。旧版 12 参数声明不可继续使用，混用会破坏调用栈。导出名为 `WM_StartMapping`，采用标准调用约定（stdcall），不要选 C 调用约定。

```text
.版本 2

.DLL命令 开始映射, 整数型, "GameWindowMapper.dll", "WM_StartMapping", , 返回0成功；关闭画布自动释放
    .参数 句柄数组, 整数型, 数组, 一维整数数组；元素为HWND原始值
    .参数 数量, 整数型
    .参数 行数, 整数型
    .参数 列数, 整数型
    .参数 画布X, 整数型
    .参数 画布Y, 整数型
    .参数 画布宽, 整数型, , 客户区物理像素
    .参数 画布高, 整数型
    .参数 裁剪X, 整数型
    .参数 裁剪Y, 整数型
    .参数 裁剪宽, 整数型
    .参数 裁剪高, 整数型
    .参数 底图或配置, 字节集, , 可直接传PNG/BMP/JPEG图片字节集；也可为空或高级配置
    .参数 配置长度, 整数型, , 取字节集长度（配置）
```

数组直接传变量，不传数组头或手工取指针。第13参数直接传字节集变量或图片常量：支持空字节集、完整PNG/BMP/JPEG图片（用作全局底图），或第3节的高级配置。数量和长度必须与真实缓冲区一致。输入数据在调用返回前保持有效；返回后 DLL 不再依赖这些变量。

## 2. 最小完整调用示例

将上面的声明加入 DLL 命令表，再加入以下子程序；调用 `启动屏幕墙 (真实句柄1, 真实句柄2)`，返回 0 表示启动成功。参数是窗口 HWND，不能填进程 ID。

```text
.版本 2

.子程序 启动屏幕墙, 整数型
.参数 窗口句柄1, 整数型
.参数 窗口句柄2, 整数型
.局部变量 句柄数组, 整数型, , "4"
.局部变量 配置, 字节集

句柄数组 [1] ＝ 窗口句柄2
句柄数组 [2] ＝ 窗口句柄1
句柄数组 [3] ＝ 0
句柄数组 [4] ＝ 窗口句柄2
配置 ＝ {  }
返回 (开始映射 (句柄数组, 4, 2, 2, 100, 100, 1000, 700, 0, 0, 800, 600, 配置, 取字节集长度 (配置)))
```

示例的 2×2 顺序是：左上窗口2，右上窗口1，左下空位，右下窗口2。输入顺序不会重排；同一 HWND 可出现多次。源窗口失效不会使后面的编号前移。

- 画布 X/Y 是屏幕位置；宽高是初始客户区物理像素，必须为正且不超过 16384。支持自由缩放与最大化。
- 裁剪 X/Y 以源窗口客户区左上角为原点，必须非负；宽高必须为正，坐标加宽高不能超过 2147483647。整个请求区域横纵分别缩放，默认拉伸铺满格子的画面区域，允许变形而不额外裁边；超出源客户区的部分按对应位置填深色。标题区单独保留，底图仍等比显示。
- 行列必须为正，乘积不超过 64，且不小于数量；数量为 0 时创建空画布。
- 空配置默认 30 FPS、统一裁剪、自动读取窗口标题、深色底图。
- 双击格子标题或画面会尝试恢复并激活对应源窗口；若系统拒绝激活，会尝试闪烁源窗口任务栏。
- 无首帧、最小化、失效或明确捕获错误显示底图和状态；没有新帧时保留最后画面。静止画面、黑场不会自动判为故障。

## 直接传图片常量的调用

第13参数可以直接填 PNG/BMP/JPEG 图片常量，无需额外包装。你提供的demo.e中的#pic是JPEG，现已支持。下面与你的示例参数一致，并显示返回码：

```text
.局部变量 返回码, 整数型

返回码 ＝ 开始映射 (句柄数组, 取数组成员数 (句柄数组), 3, 4, 0, 0, 1920, 1080, 0, 0, 200, 200, #pic, 取字节集长度 (#pic))
信息框 (到文本 (返回码), 0, "开始映射返回值")
```

这里的 `#pic` 必须是你工程中已有的 PNG/BMP/JPEG 图片常量；没有图片时改传空字节集和长度0。直传图片只设置异常/空槽位底图，不会遮住正在正常映射的画面。

句柄数组必须保存目标窗口**当前有效的 HWND**。窗口关闭重建后需要传入新句柄。无效窗口保留原格子，显示“窗口无效或已关闭”；读不到标题时显示传入的 HWND。

更新 DLL 时，先结束正在运行的旧测试程序，用 output 中的新 DLL 替换测试 EXE 同目录的文件，再重新运行；已加载进程不会自动切换到新 DLL。关闭画布后仍可再次调用开始映射，不需要退出宿主来重开画布。

## 3. 可选配置：标题、逐格裁剪、底图与帧率

只需要全局底图时直接传图片字节即可；只需要默认映射时传空字节集。需要逐格裁剪、标题、底图或帧率时，在调用前拼好一个配置字节集；不需要任何额外 DLL 命令。所有整数均为 **4 字节小端整数型**，使用 `到字节集 (整数值)` 拼接。字节集内没有指针或对齐填充。

整体顺序：**16 字节配置头 → 全局底图文件字节 → 各槽位记录**。

| 配置头字段（按顺序） | 含义 |
|---|---|
| 版本 | 固定 1 |
| 帧率 | 0 或 30 为默认 30；也可为 15、60 |
| 全局底图长度 | 后面紧跟的 PNG/BMP/JPEG 文件字节数；0 表示无底图 |
| 记录数量 | 后面的槽位记录数量；0 表示全部使用默认配置 |

每条记录是 **32 字节记录头 → 标题字节 → 槽位底图文件字节**：

| 记录头字段（按顺序） | 含义 |
|---|---|
| 槽位编号 | 1 至数量，同一编号不得重复记录 |
| 裁剪 X、Y、宽、高 | 四个整数；启用裁剪覆盖时使用，否则填 0 |
| 标题字节数 | 不含结尾零；0 表示读取源窗口标题 |
| 槽位底图长度 | 0 表示继承全局底图 |
| 标志 | 1=覆盖裁剪，2=强制显示底图，4=标题使用 UTF-16LE；需要多项时相加 |

默认标题编码为 CP936；标志包含 4 时，标题是无 BOM 的 UTF-16LE，长度仍填**字节数**。标题限 4096 个 UTF-16 单元；CP936 输入最多 16384 字节。每张图片为完整 PNG/BMP/JPEG 文件字节，最多 32 MiB、解码边长不超过 4096。整个配置最多 256 MiB，不接受多余尾部字节。图片有损坏或配置无效时，整个启动失败。

以下子程序展示：全局 PNG/BMP/JPEG 底图、第 4 格独立裁剪及中文标题“标题”。底图路径由你传入，图片文件不是运行依赖，DLL 已在启动期间读取传入字节并解码。

```text
.版本 2

.子程序 启动带配置的屏幕墙, 整数型
.参数 窗口句柄1, 整数型
.参数 窗口句柄2, 整数型
.参数 底图路径, 文本型
.局部变量 句柄数组, 整数型, , "4"
.局部变量 配置, 字节集
.局部变量 底图, 字节集
.局部变量 标题, 字节集

句柄数组 [1] ＝ 窗口句柄2
句柄数组 [2] ＝ 窗口句柄1
句柄数组 [3] ＝ 0
句柄数组 [4] ＝ 窗口句柄2
底图 ＝ 读入文件 (底图路径)
标题 ＝ { 177, 234, 204, 226 }
配置 ＝ 到字节集 (1) ＋ 到字节集 (30) ＋ 到字节集 (取字节集长度 (底图)) ＋ 到字节集 (1) ＋ 底图
配置 ＝ 配置 ＋ 到字节集 (4) ＋ 到字节集 (0) ＋ 到字节集 (70) ＋ 到字节集 (400) ＋ 到字节集 (200)
配置 ＝ 配置 ＋ 到字节集 (取字节集长度 (标题)) ＋ 到字节集 (0) ＋ 到字节集 (1) ＋ 标题
返回 (开始映射 (句柄数组, 4, 2, 2, 100, 100, 1000, 700, 0, 0, 800, 600, 配置, 取字节集长度 (配置)))
```

若需要第 4 格自己的底图，把该记录的“槽位底图长度”从 0 改为对应字节集长度，并在标题后追加该图片字节集。把示例最后的标志 1 改为 3，即同时启用裁剪覆盖和强制底图。底图文件读取失败会得到空字节集；调用前可自行判断长度，避免误以为已经设置底图。

## 4. 返回码与关闭行为

| 返回码 | 含义 |
|---|---|
| 0 | 已创建画布并启动渲染；不等待首帧或虚拟屏初始化，不保证所有源窗口都能捕获 |
| 1 | 参数、配置格式或长度无效 |
| 3 | 当前进程已有映射，或上一画布仍在完成关闭清理 |
| 4 | 网格容量小于句柄数量 |
| 5 | 配置记录的槽位编号超出范围 |
| 6 | 系统不支持 WGC |
| 7 | 图形初始化失败 |
| 8 | PNG/BMP/JPEG 解码失败或图片超过限制 |
| 12 | 内存不足、线程/窗口创建失败等内部错误 |

关闭画布后，先停止接收新窗口操作并恢复本次隐藏的全部窗口。确认恢复完成后，DLL 停止捕获、释放 GPU 与图片缓存、退出控制／渲染／UI 线程，再销毁映射对象并释放临时模块引用。恢复失败显示剩余数与“重试恢复”，画布和记录继续保留。源窗口和宿主继续运行。关闭与回收是异步过程；若马上重开返回 3，稍后再调用即可，不需要“停止”或“查询”命令。

重复调用不会更改运行中的设置，也不会创建第二个画布。多线程同时启动时最多一个成功。DLL 不保留你的数组、文本或字节集指针，不回调易语言，不修改宿主全局 DPI。动态加载的宿主可以释放自己的 LoadLibrary 引用；画布存续期间 DLL 自行保持必要引用，关闭后释放。不要在 DllMain 或加载/卸载回调中调用开始映射。

## 5. 虚拟屏隐藏／显示

画布出现后，顶部提示依次显示检查驱动、安装驱动、初始化扩展屏；滚动条不代表真实百分比。普通映射继续运行，直到就绪后才开放“隐藏窗口”。首次缺少驱动时会触发 Windows UAC，系统也可能显示驱动发布者确认；按系统提示完成授权即可，不需要手动导入证书。已安装时复用本项目设备，不接管 ToDesk 等其他软件的虚拟设备。

- 右键有效格子的标题或画面，选择“隐藏窗口”。源窗口保留大小，移入真实启用的虚拟扩展屏；窗口可以重叠，WGC 继续通过原 HWND 捕获。标题增加“虚拟屏”标记，相同 HWND 的其他格子同步标记。
- 右键选择“显示窗口”恢复保存的位置和普通／最大化／最小化状态；双击已隐藏格子先恢复，再尝试激活。隐藏时不抢占前台；最小化／最大化源会先转为可渲染的普通窗口。
- 支持 Shift+F10 打开菜单；失败卡片的按钮可用键盘操作。空槽位、无效窗口、初始化未就绪和正在操作时，相关菜单项禁用。
- 虚拟屏默认非主屏、SDR、1920×1080、60Hz；需要更大尺寸时选择能完整容纳窗口的模式，最大 7680×4320。无法容纳、权限不足或独占全屏时拒绝隐藏并显示原因。对以管理员运行的目标，宿主及辅助程序也需具备可操作该窗口的权限。

取消授权、驱动安装失败、需要重启或设备冲突时，普通映射仍可用，卡片显示原因和“重新检查”。需要重启时由你安排；错误 5 也可能表示 Windows 当前锁屏、安全桌面或远程会话不允许修改显示配置，回到本地普通桌面后重试。超过 120 秒仍未完成安装时显示超时；若关闭画布，辅助程序仍观察已启动的系统安装结束，再安全撤销本项目路径。

关闭时恢复本次全部隐藏窗口；恢复失败保留画布和虚拟屏，点击“重试恢复”。宿主异常退出由独立辅助程序恢复；若恢复仍失败，会显示简洁的恢复提示窗口，关闭该提示仅最小化，记录与重试仍保留。虚拟屏意外失效也会先恢复源窗口；原实体屏断开时改为恢复到当前可用实体屏的可见区域。多个宿主共享虚拟屏，分别管理自己的窗口；最后一个会话结束后撤销本项目活动路径并退出辅助程序，已安装驱动保留供下次使用。

## 6. 运行时文件、日志与卸载

DLL 已内嵌原始签名驱动及 x64 安装／恢复辅助程序，无需额外下载附件。运行时按需校验释放到：

```text
%LocalAppData%\GameWindowMapper\Runtime\v1\gwm_recovery.exe
%LocalAppData%\GameWindowMapper\Runtime\v1\driver\
%LocalAppData%\GameWindowMapper\Runtime\v1\Recovery-<登录SID>.<会话号>\recovery.log
%LocalAppData%\GameWindowMapper\Runtime\v1\Recovery-<登录SID>.<会话号>\recovery.bin
%ProgramData%\GameWindowMapper\VirtualDisplay\
```

打包桌面宿主可能把 LocalAppData 重定向到其应用包目录下的 `LocalCache\Local`。`recovery.log` 是 UTF-8 有界日志，可直接复制用于反馈；`recovery.bin` 是受限恢复记录，仍有窗口待恢复时不要清理运行时目录。缓存文件供下次复用，不是常驻进程；不设置开机启动。

卸载前先关闭所有画布并确认窗口已恢复。打开设备管理器，在显示适配器的属性 → 详细信息 → 设备实例路径中找到 **`ROOT\GAMEWINDOWMAPPERVDD\...`** 对应的本项目设备，再卸载该设备。不要仅凭“Virtual Display”名称删除其他软件的适配器；只有确认同一驱动包不再被任何其他设备使用时，才选择同时删除驱动程序。重新调用开始映射会按需安装。运行时缓存可在恢复完成、辅助程序退出后自行删除；ProgramData 配置保留不影响普通映射。

## 7. 你的接入测试

原易语言示例无需增加参数。先检查映射画面铺满，再右键隐藏三个目标窗口、验证大漠后台绑定及画面变化、右键／双击显示，最后关闭并重新开始。若出现问题，请提供返回码、画布错误文字、调用参数、Windows 版本、操作步骤及 recovery.log；异步捕获问题会显示在对应格子内。

本版只做短时原生验证；易语言声明与示例尚需你在易语言环境实际确认。旧版长时间测试不代表本版验收结果。
