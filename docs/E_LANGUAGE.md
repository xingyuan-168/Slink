# 易语言接入

使用 32 位易语言程序，将 `GameWindowMapper.dll` 放在最终 EXE 同目录。最低 Windows 10 1903；推荐 Windows 10/11 的当前受支持版本和显卡驱动。DLL 自带静态 CRT。DLL 没有独立进程，使用 `GameWindowMapper.ico` 设置易语言工程的程序图标；画布标题栏图标由 DLL 自行设置。

## 导入和最小调用

将 `examples/易语言DLL声明.txt` 的声明粘贴到易语言的 DLL 命令表，再把 `examples/易语言调用示例.txt` 的子程序加入工程。这些是可复制的文本源码，并非已编译的 `.e` 工程；易语言编译及运行结果由用户测试记录确认。

调用 `启动屏幕墙 (句柄1, 句柄2)`。示例排列为“句柄2、句柄1、空槽位、句柄2”，证明输入顺序就是显示顺序，重复句柄可独立裁剪。启动成功返回 0；画布异步等待首帧。窗口句柄不要求来自游戏，也不要求源窗口为 32 位。必须传入实际窗口 HWND，不能传进程 ID。

退出程序及显式卸载 DLL 前调用 `WM_Stop ()`。关闭画布也会停止映射，源窗口不受影响。可在停止后再次启动。不要在易语言 `DllMain` 或同等加载/卸载回调中启动、停止画布。

## 参数规则

| C ABI 参数 | 易语言声明与用法 |
|---|---|
| `int32_t` / `uint32_t` | 整数型，4 字节；HWND 保留原始位模式，负数显示不代表句柄无效 |
| `const uint32_t* hwnds` | 一维整数型数组，勾选“数组”；直接传数组变量，由 DLL 调用机制传连续的 4 字节元素数据地址 |
| `int32_t*` / `uint32_t*` 输出 | 整数型，勾选“传址”；调用时直接填写变量，不再手工取地址 |
| `const char*` | 文本型，内容使用 CP936，字节长度不含结尾零 |
| UTF-16 输入 | 字节集存 UTF-16LE；长度单位为 16 位代码单元，不是字节，且不含结尾零 |
| 图片输入 | 字节集存完整 PNG/BMP 文件字节，长度为取字节集长度，不是像素缓冲区 |
| UTF-16 输出 | 预分配字节集为字符容量 × 2；直接传可写字节集变量，保持声明的“字节集”类型，不传转换表达式或手工取得的整数地址 |

根据易语言官方的 DLL 命令规则，数组、文本及字节集参数无论是否勾选“传址”都会传数据地址。本声明保留数组参数的“数组”标记、字节集参数的默认标记；不需要调用方手工取指针、剥离数组头或添加偏移。“字节集勾选传址会变成二级指针”的说法不适用于该规则。数值输出参数则必须使用“整数型、传址”，并传同类型变量，以免发生临时类型转换而丢失输出。这里核对的是声明及官方规则，尚未在真实易语言环境运行验证。[易语言资料手册：Dll 命令](https://www.eyuyan.com/help/zlsc/lang.htm)

DLL 使用 `__stdcall`，导出名称没有 `_` 前缀或 `@参数字节数` 后缀。不要选择 C 调用约定。所有缓冲区在本次调用返回前必须有效；DLL 会复制所需数据，返回后允许修改或释放原变量。每次传入的数量不得超过数组实际元素数；标题长度和图片长度也不得超出真实缓冲区。

通常槽位从 1 开始。`WM_SetBackground` 的槽位 0 表示全局默认底图；传空字节集、长度 0 清除底图。`WM_GetFrameCounters` 的槽位 0 表示仅查询画布计数。标题长度 0 清除自定义标题，恢复源窗口标题。`WM_SetForceBackground` 的启用值为整数 0/1。`WM_SetFrameRate` 接受 15、30、60，初始为 30。

`WM_ReplaceWindows` 按新数组顺序整体替换，同编号标题、裁剪及底图保留。`WM_RemoveWindow` 清空槽位且不前移。`WM_AddWindow` 在数组末尾追加，返回编号为输出参数，不复用空槽位；容量不足应先扩大布局。裁剪基于客户区物理像素，宽高必须为正。

## Unicode 和错误文本

中文常用标题优先使用 `WM_SetTitleA`。若需 CP936 之外的字符，调用方自行准备 UTF-16LE 字节集并使用 `WM_SetTitleW`；例如“屏幕”的不带结尾零字节集为 `{79, 92, 85, 94}`，字符数传 2。不要把易语言的 CP936 文本直接传给 W 接口。

`WM_GetLastErrorTextW` 的容量及所需长度以 `wchar_t`（2 字节）为单位，所需长度包含结尾零。可先准备 2048 字节缓冲区，容量传 1024；返回 `GWM_BUFFER_TOO_SMALL` 时按所需长度重新分配并重试。输出需使用 UTF-16LE 解码，不能直接按 CP936 文本解释。操作失败后应立即在同一调用线程读取错误文本。

| 返回码 | 含义 |
|---|---|
| 0 | 成功 |
| 1–5 | 参数无效、未启动、已启动、容量不足、编号越界 |
| 6–8 | 系统不支持、图形错误、图片解码失败 |
| 9–12 | 正在停止、输出缓冲区不足、激活被拒绝、内部错误 |

画布状态：0 已停止，1 启动中，2 运行中，3 停止中，4 错误。槽位状态：0 空，1 等待首帧，2 实时，3 最小化，4 HWND 无效，5 捕获错误，6 强制底图，7 恢复中。`WM_GetSlotStatus` 的错误值需连同状态记录；`outFrameAgeMs` 为无符号毫秒值，`0xFFFFFFFF` 表示还没有有效帧（易语言整数显示 -1）。静态窗口长时间无新帧是正常情况。

## 帧计数和采样速率

`WM_GetFrameCounters (编号, 捕获数, 提交数, 已运行毫秒)` 返回 0 后读取三个整数型输出变量。编号 1 至槽位数量查询该槽位，编号 0 查询画布，此时捕获数固定返回 0。提交数和已运行毫秒始终属于整个画布，不是单槽位指标，也不能把多个槽位查询得到的提交数相加。

- 捕获数统计本 DLL 从该槽位的 WGC 帧池取得并处理的交付帧。一次交付不保证像素变化，也不等于源应用渲染一帧；轮询及有限帧池可能跳过源帧。
- 提交数统计整个画布成功调用 `Present` 的提交次数，不代表物理显示器实际刷新次数或每路画面内容变化次数。
- 三个输出均为 `uint32` 原始位模式，达到 `2^32` 后回绕。易语言“整数型”会把高半区显示为负数，不能将负数直接视为错误；已运行毫秒约每 49.7 天回绕一次。
- `WM_SetWindow`（包括再次传同一 HWND）、`WM_RemoveWindow` 及整数组替换会重置受影响槽位的捕获计数；重绑不重置画布提交数和运行时间。停止后重新启动会创建新画布实例，全部计数重新开始。调用方应在这些操作后丢弃旧基线，重新采样，不能把重置误算成回绕。

建议间隔 1 秒对同一槽位采样两次，先将两个有符号整数分别转成长整数；若值小于 0，再加 `4294967296`，得到无符号值。不能先在 32 位整数中相减再转成长整数。

```text
U(v) = v 转成长整数；若 U(v) < 0，U(v) += 4294967296
差值 = U(后值) - U(前值)；若差值 < 0，差值 += 4294967296
捕获交付率 = 捕获数差值 × 1000.0 / 已运行毫秒差值
画布提交率 = 提交数差值 × 1000.0 / 已运行毫秒差值
```

以上是算法示意；计算中使用长整数或双精度变量，不能把 DLL 的 4 字节输出参数改成“长整数型、传址”。例如计数从 `4294967294`（整数显示 -2）到 `3`，差值为 5；从 `2147483647` 到 `2147483648`（整数显示 -2147483648），差值为 1。时间差为 0 时跳过本次计算。差值法要求两次采样间没有重绑或重新启动，且任一计数实际增量小于 `2^32`；查询失败或实例变化后重新建立基线。各项查询用于诊断采样，不是原子同步的显示时序测量。

## 独立宿主与测试反馈

先用发布包的命令行宿主检查一个 HWND（示例句柄需替换）：

```powershell
./mapper_demo.exe --hwnds 0x00123456 --rows 1 --cols 1 --region 0 0 800 600 --title 1 "窗口一" --duration 30
```

多个句柄用逗号分隔。不指定 `--duration` 时，关闭画布或 Ctrl+C 退出。控制台每秒输出画布和槽位状态，可重定向到本地日志。截图或反馈时附上：Windows 版本、源应用名称及 x86/x64、源 HWND、裁剪参数、窗口是否最小化、DLL 返回码、槽位状态和测试操作。不要提供源窗口中的敏感内容。

用户验收依次测试：加载启动；乱序数组及重复 HWND；按编号改裁剪、改标题、换 HWND；传 PNG/BMP 字节集；最小化与恢复；双击激活；关闭重开；停止后退出易语言。记事本和动态源自测结果见项目测试报告，其他窗口兼容性以实际结果为准。
