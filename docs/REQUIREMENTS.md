# Requirements

## 目标

requirement_id: REQ-GWM-001

将调用方传入的 HWND 对应客户区区域，实时合成到同一画布，供 32 位易语言调用。不限于游戏，但不承诺所有窗口都允许捕获。

## 需求

1. **不可修改规则**：易语言数组下标 = 槽位编号，从 1 开始；内部 `index=slot-1`、`row=index/cols`、`column=index%cols`。禁止按句柄、标题、Z序或收帧顺序排序。
2. 失效、移除、最小化或捕获失败的槽位不挤压；重复 HWND 合法，可使用不同区域。
3. 裁剪参数为源客户区物理像素，统一默认值与逐槽位覆盖并存。宽高必须为正；部分越界按原请求区域比例留背景。
4. 创建独立原生画布；初始位置、客户区宽高、行列可设置，支持最大化和自由缩放，图像等比居中。
5. 每格上方显示编号与标题；自定义非空标题优先，否则读取窗口标题。长标题省略。
6. 支持默认底图及逐槽位 BMP/PNG/JPEG 字节集、强制底图。未收首帧、失效、最小化、明确捕获错误使用底图；无新帧保留末帧，不以静态/全黑判断故障。
7. 双击格子的标题或画面，按布局直接得到槽位 HWND，最小化时恢复并尝试激活；被系统拒绝时尝试闪烁源窗口任务栏。
8. HWND、ROI、标题、底图在启动时一次传入；运行中不更新，需要调整时关闭后重新启动。配置记录按槽位应用，不改变数组映射顺序。
9. C ABI / x86 stdcall / 唯一未修饰导出 WM_StartMapping / 32 位状态码；并发启动最多一个成功，返回前复制输入。不公开停止或查询接口，不在 DllMain 等待线程。
10. 使用 input/LOGO.png 制作等比完整多尺寸 ICO，嵌入画布及测试 EXE；宿主进程图标由易语言 EXE 设置。
11. 每进程一个画布；用户关闭后自动释放图形、捕获、窗口、线程和映射对象，不关闭源窗口和宿主，不依赖下次启动清理。回收期间重复启动返回已启动。
12. 正式交付严格只有 output/GameWindowMapper.dll 与 output/使用说明.md。开发资产留在仓库；用户 demo.e 原样整理到 examples，不覆盖。

## 验收标准

见 TEST_PLAN.md。本轮按用户要求仅做单导出、显示、关闭释放及重开、交付内容短验证；历史记事本和动态源结果单独标注，长时间压力测试不追加。其他应用和易语言由用户自行验证。
