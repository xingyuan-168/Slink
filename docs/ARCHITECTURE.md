# Architecture

Windows 10 1903+ / Windows 11，C++20 / MSVC / CMake / x86 / 静态 CRT。每宿主进程一个原生画布；WGC 捕获，D3D11 GPU 合成，D2D/DirectWrite 文字，WIC 解码。

## 数据流

单个 WM_StartMapping → 校验数组和可选配置字节集 → 复制为有序槽位与解码图片 → 创建映射 → WGC 客户区裁剪 → GPU 横纵分别缩放铺满格子 → 画布。

数组不排序、不去重、不补空；同一 HWND 可以独立裁剪。配置在启动时固定，删除运行中修改/查询接口。状态仍由引擎内部维护，用于失效、最小化、首帧等待、捕获失败及底图显示。

## 线程和自动释放

- 接口锁保护单实例启动；有活动实例时返回已启动，包括最后清理阶段。
- 回收线程拥有 Engine。它启动 UI 线程，等待初始化结果通知调用方，再等待 UI 线程结束。输入已经完整复制，启动不等待第一帧。
- UI 线程创建画布、管理消息；渲染线程初始化 MTA 并拥有 WGC/D3D/D2D 资源。
- WM_CLOSE 先请求停止，渲染线程销毁捕获会话、帧池、纹理、图片缓存和设备后通知 UI 关闭；UI 销毁窗口、注销窗口类、释放非共享图标并结束。
- 回收线程 join UI，销毁 Engine（含配置及线程对象），然后清除活动标记。没有全局遗留 Engine，也不等待下一次 API 调用回收。
- 回收线程在创建前获取 DLL 临时引用；所有工作线程退出后使用 FreeLibraryAndExitThread 原子释放和退出，防止调用方提前 FreeLibrary 导致执行已卸载代码。回收线程句柄在创建后关闭，不需宿主保存。
- DllMain 仅保存模块句柄，不创建线程、初始化 COM/图形或等待。DPI 感知只设在自有 UI/渲染线程，避免改变宿主全局。
- 释放捕获对象后、CoUninitialize 之前清理 C++/WinRT 工厂缓存；否则宿主保留 DLL 时，下一次 IsSupported 可能调用已随 COM 关闭失效的工厂指针。正常关闭与初始化失败路径都执行此清理。

## 捕获和呈现

每槽位独立 WGC CreateForWindow + CreateFreeThreaded 帧池，两个缓冲；渲染轮最多取两帧，最新纹理复制到 GPU 自有纹理。没有 FrameArrived / Closed 外部回调。图形 immediate context 串行访问，不做生产逐帧 CPU 拷贝。

客户端原点、实际捕获边界和纹理尺寸共同决定裁剪偏移，不硬编码标题栏。窗口最大化状态或 DPI 改变时重建完整捕获会话，避免 WGC 沿用旧非客户区变换；大小过渡时旧纹理与几何成对保留，跳过部分帧。完整请求 ROI 对应整个格子画面区域，横纵分别缩放，不额外裁边；越界部分按相同坐标变换保留深色。底图和 LOGO 仍等比显示。

系统标题使用 InternalGetWindowText，避免同步跨线程读取宿主标题造成等待环。图标使用非共享 LoadImage 句柄，窗口类注销后 DestroyIcon。布局命中和渲染使用同一矩形计算。

## 故障

无新帧保留末帧，黑场/静止不判故障。未收帧、最小化、明确失败、失效和强制底图显示占位状态。观察到 HWND 失效即保持失效，不自动绑定复用句柄；需要关闭后重新开始。

图形设备失效最多连续重建3次，失败后画布仍可关闭。无桌面截图降级。原生短测试通过 WGC 再捕获自有画布并回读 GPU 像素，避免桌面 DC 读到覆盖应用；回读只属于测试，生产没有逐帧 CPU 图像处理。采样帧率可在启动配置中设15/30/60，默认30，不承诺源窗口或显卡达到目标帧率。

## 虚拟显示与独立恢复后端（REQ-GWM-002，画布接入待审批）

x86 DLL 嵌入原始 AMD64 驱动包、MIT 许可和静态 CRT x64 gwm_recovery.exe。SHA256 固定校验，运行时原子释放到用户 LocalAppData/GameWindowMapper/Runtime/v1；目录受限，拒绝重解析点和硬链接，不改动原驱动字节。打包桌面宿主可能重定向 AppData；通信身份比较进程映像与已验证辅助程序的打开文件 ID 和卷编号，而非路径拼写。

同一交互登录 SID + Windows session 共享一个恢复辅助进程，命名管道仅本登录及 SYSTEM 可用，核验客户端 PID、用户、登录身份和进程创建时间。协议为内部固定宽度格式，不增加 DLL 导出。串行工作队列负责窗口操作、退出恢复；独立初始化线程负责驱动安装与扩展路径；状态读取不等待长操作。回复有有界确认，连接容忍管道实例轮换的短暂空隙。

宿主启动一次登记 HWND 白名单，恢复日志先持久写入并刷新再移动窗口，恢复成功后才移除记录。原始位置包含 WINDOWPLACEMENT、物理矩形、显示器信息；进程创建时间、线程/窗口类和窗口属性 cookie 防止 HWND 复用。重复槽位共享同一窗口记录。宿主退出或虚拟屏丢失时由独立进程恢复；失败保留记录并重试。各宿主分别拥有租约，最后租约及窗口记录清空后撤销本项目活动路径并退出辅助进程，驱动保留。

设备身份记录在 HKLM/SOFTWARE/GameWindowMapper/VirtualDisplay（64 位视图），保护配置位于 ProgramData/GameWindowMapper/VirtualDisplay；安装仅定向本项目根设备。DisplayConfig 修改当前拓扑中本项目目标，保留其他路径、主屏与几何。首次系统可能自动克隆，创建者在无隐藏窗口时先撤销该路径，再建立非主扩展屏。首装允许 Windows 原生发布者确认，不导入根证书、不修改系统签名策略。

当前后端与真实驱动已短测通过；Engine 仍采用上文原关闭流程。正式画布将增加自有控制线程调用 RecoveryClient，并在 Release 确认恢复完成后才触发原渲染停止流程。新增菜单、进度和恢复失败交互必须先取得本次原型批准；不得把后端测试结果描述为已交付这些交互。
